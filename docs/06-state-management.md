# State Management

## Store Technology

The application uses Zustand with the `persist` middleware.

Main store:

```text
src/stores/session.store.ts
```

Dialog store:

```text
src/stores/ui.store.ts
```

## Player Session

The persisted session type is defined in `src/types/session.ts`.

```ts
export interface PlayerSession {
  id: string;
  name: string;
  course: string;
  storyId: number;
  currentStage: number;
  usedQRs: string[];
  reflection: string;
  phase: GamePhase;
}
```

## Session Fields

| Field | Purpose |
| --- | --- |
| `id` | Local unique player session ID generated by `crypto.randomUUID()`. |
| `name` | Student name from registration. |
| `course` | Student course/program from registration. |
| `storyId` | Numeric index of the assigned story in `quests.json`. |
| `currentStage` | Zero-based quest stage index. |
| `usedQRs` | Marker IDs already used by this player. |
| `reflection` | Student reflection submitted on the finish page. |
| `phase` | Current game phase: `registration`, `quest`, `finish`, or `completed`. |

## Game Phase

Defined in `src/types/game.ts`.

```ts
export type GamePhase = "registration" | "quest" | "finish" | "completed";
```

The implementation does not use a separate `completed: boolean`. Completion is represented by:

```ts
phase: "completed"
```

## Persist Behavior

The session store is persisted under the key:

```ts
name: "arg-session"
```

This means the player can refresh or briefly leave the app without losing:

- assigned story
- current stage
- used QR markers
- reflection
- phase

Because there is no backend, this persistence is local to the browser/PWA installation.

## Store Actions

| Action | Responsibility |
| --- | --- |
| `startSession(name, course)` | Creates a new session and assigns a random story. |
| `revealAnswer(rawQrValue)` | Validates QR, checks phase/session, checks marker reuse, stores used marker. |
| `completeStage()` | Advances the current stage and moves to `finish` after the final quest. |
| `unlockFinish()` | Directly sets `phase` to `finish`; currently present but not part of the normal quest route flow. |
| `saveReflection(value)` | Stores reflection and sets `phase` to `completed`. |
| `reset()` | Clears the session. |

## Derived Game Data

`useGame()` in `src/hooks/useGame.ts` reads the current session and derives:

- current story
- current quest
- progress object

It uses helpers from `src/lib/game.ts`:

- `getCurrentStory(session)`
- `getCurrentQuest(session)`
- `getProgress(session)`

## Dialog State

`src/stores/ui.store.ts` stores one global dialog payload.

`GameDialog` renders globally in `src/routes/__root.tsx` after the route outlet.

Dialog variants:

- `success`
- `warning`
- `error`
- `info`

Quest answer validation uses this store to show success and error feedback.
